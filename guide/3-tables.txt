3. Tables

A listing is a table. Its columns are name, kind, folder, size and modified, and each row is one record.

Table commands take a table from the pipe and answer another:

  ls | where $row.kind eq folder
  ls | sort size desc
  ls | select name size
  ls | distinct kind
  ls | group kind

The argument to where is a question about each row. $row is the row being asked about, and the question is written with words rather than symbols: eq, ne, gt, ge, lt, le, like and has compare, and and, or and not combine.

  ls | where $row.size gt 0 and $row.kind ne folder
  ls | where $row.name like *.txt

A question has to read $row and answer true or false, so these two fail rather than answer an empty table, and under each the terminal says what you probably meant, with the corrected line as a chip. Tapping it puts the line in the input; it does not run it.

  ls | where kind eq folder
  ls | where $row.kind

A question that is asked properly and matches nothing answers an empty table, and says why under it: here, the kinds there are, and folder as a chip.

  ls | where $row.kind eq foldr

Tapping a column header re-sorts the table on screen. Tapping a cell puts it in the line.
